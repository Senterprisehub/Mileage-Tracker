Mileage Tracker is an Android app for automatic and manual mileage logging, vehicle expense tracking, and audit-ready tax reports. It tracks GPS drives in the background, calculates fuel and maintenance costs, supports multiple vehicles, and keeps trip records on the device.

The repository also includes a lightweight project website in `index.html` and can build a downloadable APK directly through Gradle.

## Features

- **Automatic GPS drive detection** with a persistent foreground location service
- **Manual trip entry** with vehicle, category, addresses, odometer values, tolls, parking, and notes
- **Multiple vehicles** with vehicle type, fuel type, fuel efficiency, and wear cost settings
- **Trip categorization** for business, personal, medical, and charity drives
- **Live cost estimates** for fuel and maintenance using configured prices and vehicle efficiency
- **Monthly mileage summaries** with month navigation and period filters
- **Saved places** and configurable trip geofencing
- **PDF and CSV reports** for sharing or exporting to a user-selected destination
- **Full backup and restore** from the app settings
- **Android backup support** with data extraction and backup rules
- **Boot and package-update resume support** for configured automatic tracking
- **Unit conversion** between supported distance, volume, and fuel-efficiency units
- **Device-first storage** using Room; no subscription or cloud account is required

## Requirements

- Android 7.0 / API 24 or newer
- Android Studio with an Android SDK containing API 36
- JDK 11 or newer for Gradle builds
- Internet access only for optional live fuel-rate lookup and normal Android network features

For background tracking, the app requests:

- Precise and approximate location
- Background location / “Allow all the time”
- Physical activity recognition
- Location foreground-service permission
- Notifications
- Battery optimization exemption
- Boot-completed access

Android may present these permissions separately and some features require them to remain enabled for reliable background operation.

## Build from source

```bash
git clone https://github.com/Senterprisehub/Mileage-Tracker.git
cd Mileage-Tracker
./gradlew assembleDebug
```

The Gradle configuration copies successful debug builds to:

```text
apk/app-debug.apk
```

Build a release APK:

```bash
./gradlew assembleRelease
```

The release build is configured to use environment-based signing values:

```bash
export KEYSTORE_PATH=/absolute/path/to/upload.jks
export STORE_PASSWORD='your-store-password'
export KEY_PASSWORD='your-key-password'
./gradlew assembleRelease
```

If `KEYSTORE_PATH` is not set, Gradle expects `my-upload-key.jks` at the repository root. The signing alias is `upload`.

To bypass signing during local development, use `assembleDebug`. A `debug.keystore` may be generated by the Android build tools if it is not present.

## Application architecture

### Android UI

`MainActivity` owns the top-level Compose navigation and permission-launch flows. The three primary tabs are:

- **Drives** — dashboard, live drive controls, manual trips, trip details, and reports
- **Vehicles** — add, edit, select, or delete vehicle profiles
- **Settings** — tracking, units, country/city, fuel prices, backups, and saved places

The UI is implemented with Jetpack Compose and Material 3. Feature screens are grouped under `app/src/main/java/com/example/ui/`.

### State and data

`MileageViewModel` exposes lifecycle-aware state to the Compose UI. Room-backed entities and DAOs under `data/local/` store trips, GPS points, vehicles, settings, saved places, and related records on the Android device.

The app uses Kotlin coroutines for asynchronous database and tracking operations. `Google Play services Location` supplies location updates for foreground and background tracking.

### Background tracking

`MileageTrackingService` is declared as a foreground location service in `AndroidManifest.xml`. It manages:

- Activity and motion-aware drive detection
- GPS point collection and distance calculation
- Auto-resume behavior
- Pause and stop handling
- Persistent notifications

`AutoResumeReceiver` listens for boot completion and package replacement broadcasts. `AutoResumeManager` and `TrackingState` coordinate whether monitoring should restart.

### Reports and export

The export UI supports:

- PDF mileage reports
- CSV trip and expense data
- Share sheets
- Custom storage destinations through Android Storage Access Framework
- Full JSON-style app backup and restore workflows

Report generation is implemented under `app/src/main/java/com/example/util/PdfReportGenerator.kt`.

## Privacy and storage

Trip, vehicle, place, and settings data are stored locally in the app's Room database and Android-managed backup areas. The app does not require an account or paid subscription.

Internet or network access may be used for live fuel-price lookup and report sharing. GPS location data is used for drive tracking and is not sent to a repository-hosted backend by the application source.

For security when distributing a signed APK, keep upload-keystore passwords and release signing credentials out of source control.

## Configuration notes

- The Gradle Secrets plugin reads `.env` and falls back to `.env.example`; do not commit private API or signing values.
- Google Services configuration is optional/warned at build time because the missing-services strategy is permissive.
- Release APK shrinking/minification is currently disabled.
- The app uses a debug signing configuration for debug builds and environment-based signing for release builds.
